This document describes how to run the SGLang serving runtime on Apple Silicon
using PyTorch MPS. Apple Silicon uses the standard SGLang scheduler,
`TpModelWorker`, Torch `ModelRunner`, RadixCache, KV pools, logits processing,
and sampling path. There is no separate MLX runner or model loader. SGLang
Diffusion also uses PyTorch MPS; see its
[installation guide](/docs/sglang-diffusion/installation#platform-specific-apple-mps).
If you encounter issues or have questions, please [open an issue](https://github.com/sgl-project/sglang/issues).

## Prerequisites

The SRT MPS backend requires Apple Silicon with macOS 14 or newer and stable
PyTorch 2.13.x. The `srt_mps` extra installs the tested Torch 2.13 release.
SGLang validates the Torch version, MPS availability, and required memory APIs
during argument initialization and stops before resolving or downloading a
model when the runtime is incompatible.

Building the optional native Metal kernels in `sgl-kernel` requires the Metal
shader compiler from the full Xcode application. The standalone Xcode Command
Line Tools are not sufficient. After installing Xcode, select it with:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
```

Verify the compiler with `xcrun -sdk macosx metal --version`.

## Install SGLang

You can install SGLang using one of the methods below.

### Install from Source

```bash
# Use the default branch
git clone https://github.com/sgl-project/sglang.git
cd sglang

# Create and activate a virtual environment
uv venv -p 3.12 sglang-metal
source sglang-metal/bin/activate

# (Optional) Compile sgl-kernel
uv pip install --upgrade pip
uv run python/sglang/kernels/aot/setup_metal.py install

# Install sglang python package along with diffusion support
rm -f python/pyproject.toml && mv python/pyproject_other.toml python/pyproject.toml
uv pip install -e "python[all_mps]"
```

## Launch of the Serving Engine

Launch the server with:

```bash
python -m sglang.launch_server \
  --model-path Qwen/Qwen3-0.6B \
  --device mps \
  --dtype bfloat16 \
  --attention-backend torch_native \
  --disable-cuda-graph \
  --host 0.0.0.0
```

**Key Parameters Explained:**

1. `--device mps` selects Apple's PyTorch MPS device explicitly.
2. `--attention-backend torch_native` uses the baseline Torch attention path.
3. `--disable-cuda-graph` makes the eager execution mode explicit. CUDA Graph
   is not available on MPS.

Overlap scheduling is disabled automatically on MPS. Prefix caching remains
enabled and uses the ordinary SGLang RadixCache lifecycle.

## Quantization

The MPS backend currently requires unquantized Torch weights. Omit
`--quantization` or pass `--quantization unquant`.

## Benchmarking with Requests

`sglang.benchmark.one_batch` calls the standard Torch `ModelRunner`
directly without going through the scheduler.

`sglang.benchmark.offline_throughput` exercises the scheduler and prefix-cache
path. Overlap scheduling remains disabled on MPS.

### Throughput Testing

Basic synchronous one batch throughput:
```bash
python -m sglang.benchmark.one_batch \
  --model-path Qwen/Qwen3-0.6B \
  --device mps \
  --attention-backend torch_native \
  --disable-cuda-graph \
  --tp-size 1 \
  --batch-size 1 \
  --input-len 60 \
  --output-len 10
```

Scheduler-based offline throughput:
```bash
python -m sglang.benchmark.offline_throughput \
  --model-path Qwen/Qwen3-0.6B \
  --device mps \
  --attention-backend torch_native \
  --disable-cuda-graph \
  --num-prompts 8
```
